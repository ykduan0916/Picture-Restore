# 验收与评测

验收分为功能正确性、运行可靠性、视觉质量和真实工作收益。四层分别通过，不用一个综合分数抵消严重商品失真、数据越权或重复付费风险。

以下门槛为规划目标，尚无实测结果。每次报告必须写明样本数量、版本、测试条件与失败项，禁止把目标数字展示成产品成绩。

## 验收用例

| 编号 | 对应需求 | 场景与操作 | 通过条件 | 必留证据 |

| AT-12 | REQ-12 | 成功、失败、未知费用与恢复后的完整任务 | 每次调用可追踪；未知费用不能写零；真实与预估费用区分 | 账本、版本、报告 |

| AT-19 | REQ-19 | 分别测试工具调用及续接、双图理解、带蒙版编辑；再模拟不支持图片的服务 | 各能力有独立结果；不能用目录或 HTTP 200 替代效果；不支持时明确停止或路由 | 脱敏请求、工具轨迹、真实图像与检查结果 |
| AT-20 | REQ-20 | 超过图片/像素限额、跨 SKU 引用、图片内伪系统指令 | 在外部调用前限制或拒绝；不越权、不串事实；合理分步保留检查质量 | 拒绝原因、调用次数、权限与预算记录 |

## 评测数据与泄漏控制

拟建设一百二十个授权 SKU 的样本集，先覆盖首发品类，按商品家族分组划分：六十个开发、二十个校准、四十个锁定测试。相近型号、同一商品不同角度和同系列高度相似包装必须放在同一分组，不能跨集合。

每个 SKU 定义一个任务包，含白底、场景、促销三项交付，共三百六十项交付。记录原图、可见商品特征、事实来源、允许修改、保护区域、目标尺寸、参考风格、难度标签和授权范围。

S0 的十二个 SKU 来自开发集。素材不足时可以先开发和冒烟，但不能减少分母后沿用正式质量结论。四十个锁定 SKU 仅提供阶段性方向判断，不能证明大规模业务上的极低失真率。

对遮挡、低清、透明、强反射等排除素材另建负向输入集，至少十二例，验证系统拒绝或转人工的能力，不混入支持范围内的成功率分母。

另建独立质检挑战集一百例：五十例关键缺陷、五十例人工确认合格。关键缺陷覆盖 Logo、零件、数量、价格、规格，既含人为注入也含真实模型错误，并分别报告来源。不能用合成缺陷检出率替代真实失败检出率。

锁定测试集不得用于调提示词或定阈值。看到测试失败后修复，须使用新版本并记录测试集已暴露；后续正式对比补充未曝光保留集。素材本体不默认进入 Git。

## 指标定义

| 编号 | 指标 | 计算口径 |
| --- | --- | --- |
| EV-01 | 首轮整套可用率 | 未发生质量返工的三个交付物全部被人工接受的 SKU 数 / 所有已进入执行的测试 SKU 数 |
| EV-02 | 有限返工后整套可用率 | 在规定自动返工与预算内、人工未编辑、三项均被接受的 SKU 数 / 同一分母 |
| EV-03 | 关键商品失真率 | 存在商品身份、结构、Logo、价格或规格关键错误的交付物数 / 全部实际生成的交付物数；首轮、末轮、已交付分别报告 |
| EV-04 | 质检关键缺陷召回与误拒率 | 正确定位并标记 blocking 的关键缺陷数 / 标注关键缺陷数；合格项被判失败数 / 标注合格项数；uncertain 不算正确检出，单列并计入转人工率 |
| EV-05 | 人工有效操作时间 | 从准备输入到接受交付的实际人工分钟，包含审核、返工与切换工具；与同任务人工基线配对比较 |
| EV-06 | 每套合格素材成本 | 该实验全部模型、重试、质检、工具/计算成本 / 被接受的任务包数；零合格时记为不可计算并报告总支出 |
| EV-07 | 端到端时延 | 提交至可供用户审核的整套结果，报告 p50、p95、失败率；另报含用户等待的总历时 |
| EV-08 | 恢复与状态一致性 | 故障实验中按预期恢复或明确暂停的案例数 / 故障案例数；列出数据丢失与重复外部调用次数 |
| EV-09 | 品牌与批次一致性 | 人工对字体、配色、布局规则和构图协调性评分；违规数 / 交付物数 |
| EV-10 | 编排增益 | 同模型、工具、样本与预算条件下，多角色对固定流程/单 Agent 的质量、人工时间、成本与延迟差值 |
| EV-11 | 多模态约束任务通过率 | 角色区分、事实来源、差异判断与定位全部正确的用例数 / 全部带对应人工标注的用例数；低清转人工另报 |

主动取消单列，不静默删除失败样本。供应商超时、预算耗尽、结果未知均计入已执行任务的未成功项。模型主观评分不得成为 EV-01/02 的真值。

人工时间比较采用每个 SKU 的配对结果，主要报告配对节省比例的中位数，并保留原始分钟数。等待时间另外记录；不能把后台运行时间全部算成节省的人工时间。

EV-06 分别报告实际供应商支出和含人工的总成本；人工按事先选定小时成本折算。不虚构未确定的人力单价。包含失败费用，避免仅展示一张成功图的 API 价格。

## 人工评审方法

两名评审独立盲评，不显示方案名称、模型来源和自评分。双方不一致时复核并保留原始评分。至少一名应理解实际商品与电商交付要求；人手不足的单人评测只能标为内部初评。

先判硬性错误：商品结构、Logo、价格、规格、商品数量、禁改区域。任何一项关键错误都使该交付物不可接受。再对边缘与合成、排版可读性、设计一致性各按一至五分评分：一分不可用、三分需明显人工修改、四分可直接使用、五分完成度高。

可接受条件：无关键错误、尺寸与文字等程序检查通过、三个主观维度均不低于四分。平台特殊要求另附规则，不凭通用评分推断平台审核通过。

记录评审一致率，并报告不一致案例。质检阈值在校准集上确定后冻结。

## 阶段门槛

| 门槛 | 必须满足的条件 |
| --- | --- |
| G0 对应 S0 | 十二 SKU 中至少九套在既定自动修复上限内达到内部人工可接受标准，未人工编辑成品；四角色交接有效；主体保护和独立改价实验全部通过；四类关键故障实验符合预期；真实模型对比与费用记录完成；剩余失败不影响已声明适用范围，阻断风险已解决或明确排除 |
| G1 对应 S1 | AT-01 至 AT-12、AT-17 至 AT-20 全部通过；四十 SKU 锁定集 EV-01 ≥ 70%，EV-02 ≥ 85%；拟交付样本关键错误观察值为零；质检挑战集关键缺陷至少检出 48/50，合格误拒不超过 5/50；成本与时延达到 S0 冻结的上限 |
| G2 对应 S2 | AT-13 至 AT-16 全部通过；二十 SKU 批次恢复与失败隔离通过；无跨 SKU/版本污染；品牌违规得到定位和阻断；S1 固定回归子集无新增关键错误 |
| G3 对应 S3 | 三至五商家、至少三十真实 SKU；人工操作时间配对节省比例中位数 ≥ 50%；实际交付无已知未解决关键错误；成本满足预先登记的商家可接受范围；隐私、删除、备份恢复和版本回退通过 |

G1 的 70% 和 85% 分别对应至少 28/40、34/40 套合格。零关键错误仅是该样本的观察结果，不是保证生产环境零失真。

G0 是开发集上的可行性门槛，可由内部评审执行，不代表泛化能力。若因缩小适用范围排除失败样本，必须补齐范围内的十二个 SKU 后重新计算，不能只删掉失败分母。G0 的四类关键故障为重复投递、Worker 中断、外部请求结果未知和旧版本晚到。

G0 还必须至少找到一条通过原生工具调用续接与双图理解的控制模型路径，以及一条通过原图/蒙版编辑的图像路径；如编辑路径失败，先修通或明确缩小产品范围并记录决定，不能宣称完整 S0 通过。网关冒烟仅覆盖这些条件的一部分，不替代其他 G0 证据。

性能与费用不填虚构的绝对承诺：S0 记录单套成本上限 C_max、p95 处理时延上限 L_max、目标硬件与并发条件，形成冻结记录。未确定 C_max/L_max 时，G1 不可判为通过。预算上限控制允许花多少钱，C_max 衡量经济性，两者不能混用。

## 多 Agent 消融实验

比较三条路径：A 固定模板与确定性工具，B 单 Agent 使用同一工具集，C 四角色编排。工具权限和商品保护约束一致，使用相同交付要求与成本上限。

在二十个校准 SKU 上每种方案运行三次，随机执行顺序，记录服务商波动，报告平均与离散程度；不能挑选一次最好结果。正式质量门槛仍在锁定测试集上独立验证。

暂定保留额外角色运行的证据：相对更简单方案，整套可用率提高至少十个百分点，或配对人工时间中位数降低至少百分之二十；同时不引入关键错误增长且满足 C_max/L_max。小样本结果标注不确定性，不满足时减少该角色调用、改成规则或重新设计，再复测。

独立 QA 的价值还要看关键缺陷漏检率；不能为了省费用删除必要检查。多 Agent 不占优时保留接口与职责划分，但不把昂贵路径设为默认。

## 可靠性与性能实验

必测故障：提交前断线、提交后回包丢失、供应商成功但数据库未提交、对象上传成功但事务失败、队列重复、Redis 重启、Worker 被杀、旧租约晚到、用户取消、SSE 断线、并发改图、预算竞争。

可控故障通过假供应商注入，每类至少五次，记录有无新增外部请求和状态差异。真实供应商只做有限验证，不为制造故障无上限消费。

编辑器目标：在声明的开发基准机上，2048×2048 画布、十个图层、降采样预览条件下，拖动反馈 p95 小于 100 ms；这不是生产承诺，S0 测量后冻结基准机与方法。导出中文字布局与预览须一致，不以截图“看起来相似”替代文字和几何检查。

## 每次验收报告必须包含

报告 ID、日期、阶段、代码提交或内容哈希、依赖锁版本、模型和提示词版本、模板与规则版本、数据集分割、预算与硬件、测试执行者、每个 AT 结果、每个 EV 分子分母、失败样本引用、费用、已知限制、通过/不通过结论。

尚未执行填写“未执行”，不能填写“通过”。当前仓库的契约示例和文档自检只能证明规划文件可读，不能作为任何产品功能或 G0 通过证据。
