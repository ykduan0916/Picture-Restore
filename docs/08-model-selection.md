# 模型需求与网关初选

核查日期：2026 年 10 月 15 日。用户为本项目提供了一组 New API 网关连接信息。先查询模型目录，随后按用户明确要求进行了十一条真实接口请求，使用自制非敏感测试图。结果见 [网关能力实测](10-gateway-smoke-results.md)。

结论：gpt-6.1-sol 与 claude-sonnet-5-5 已通过工具调用续接和双图理解冒烟，暂不需要增加通用大模型。三个图像编辑候选在当前分组均返回无可用通道，需补齐或修复图像编辑通道。专用抠图与蒙版能力需本地组件或专门服务补齐；实际结算价格和真实商品效果仍待验证。

## 需要的模型能力

| 能力 | 对应角色或工具 | 必须验证的要求 |
| --- | --- | --- |
| 规划与工具选择 | 任务规划、修图执行的控制逻辑 | 约束理解、结构化输出、工具参数准确、缺失事实不编造 |
| 图片理解与设计 | 视觉设计、素材诊断 | 接收商品原图、理解构图与品牌参考，输出可执行 DesignSpec |
| 多图对照 | 质量验收 | 同时观察原图和结果、定位关键变化、不确定时转人工 |
| 图像生成与编辑 | 被修图执行 Agent 调用的工具 | 背景生成、原图参考、局部编辑、真实可解码图像输出 |
| 前景提取与蒙版 | 独立图像工具 | 透明通道、边缘质量、保护商品细节、可人工修正 |
| OCR 和几何检查 | 质检工具 | 字段核对、位置与溢出检测；不能只靠大模型泛泛打分 |

四种 Agent 是四种职责，不要求四种不同模型。修图执行 Agent 需要一个能看图与调用工具的控制模型，另调用专用图像模型；图像模型本身不承担工作流控制。

## 首轮候选组合

| 用途 | 初选 | 选择依据与限制 |
| --- | --- | --- |
| 任务规划与修图控制 | gpt-6.1-sol | Responses 原生工具调用、结果续接及双图冒烟已通过；后续验证复杂计划与严格 schema |
| 视觉设计 | gpt-6.1-sol，独立设计上下文 | 初期复用模型，减少接入变量；是否能给出有效版式需看本项目样本 |
| 质量验收基线 | gpt-6.1-sol，独立只读上下文 | 先建立统一基线，生成和检查仍可能相关误判；必须人工标注评测 |
| 独立质检对照候选 | claude-sonnet-5-5 | Chat Completions 工具续接与双图冒烟已通过；真实商品质检准确性待评测 |
| 精细图像编辑 | gpt-image-2.5-sunburst | 当前 token 的编辑请求 503，无可用通道；修复后才做质量对比 |
| 背景生成与速度对照 | gpt-image-2.5-flare | 当前 token 的编辑请求 503，无可用通道；修复后才做质量对比 |
| 兼容性回退候选 | gpt-image-2 | 编辑回退请求同样 503；目前不能作为可调用回退路径 |

首轮正式图像效果对比限 Sunburst 与 Flare 两个候选；本轮通道诊断额外检查了 gpt-image-2。其他推理候选暂不默认调用；不从模型名称推断贵或便宜，最终以实际费用与质量决定。

gpt-5.6-luna 的工具与视觉请求均因当前分组无通道而失败。deepseek-v4-flash、glm-5.3-flash 等尚未测试，可后续作为简单文本任务降本候选。名称不完整的 claude- 暂不纳入初选，先明确真实映射。

GPT-6.1 Sol 的工具调用应使用 Responses API；官方说明 Chat Completions 支持该模型但不支持工具调用。不能因为兼容普通聊天就认为可以直接接入 Agent 工具循环。[官方模型页](https://developers.openai.com/api/docs/models/gpt-6.1-sol)

OpenAI 官方将 Flare 作为速度优先候选、Sunburst 作为质量优先候选，两者支持生成和编辑。这里是初选依据，不是本项目的胜出结论。[官方图像指南](https://developers.openai.com/api/docs/guides/image-prompting)

图像蒙版是模型编辑的指导，不保证严格像素边界。即使实际接口支持 mask，商品保真仍应依靠原商品层、保护区域和合成策略。[官方编辑说明](https://developers.openai.com/api/docs/guides/image-generation)

## 最需要验证的接口

公开 pricing 的 supported_endpoint 仅列 /v1/chat/completions 和 /v1/messages；实际 Responses 调用已成功，说明这份公开元数据不能作为完整路由清单。

| 接口或能力 | 为什么需要 | 最小实测 |
| --- | --- | --- |
| /v1/responses | GPT-6.1 Sol 工具调用 | 强制调用一个无副作用测试工具，回传结果并完成一次续接 |
| 严格结构化输出 | TaskContract、DesignSpec、QualityReport | 返回指定 schema，验证类型、必填字段和拒绝行为 |
| 图片及多图片输入 | 设计、诊断、质量验收 | 使用本地产生的几何测试图辨色定位，再比较一对有明确差异的图 |
| /v1/images/generations | 背景与候选素材 | 一张明确尺寸、明确质量的背景图，验证 MIME、像素与 usage |
| /v1/images/edits | 参考原图和局部编辑 | 自有测试图加蒙版，观察目标区域和保护区域，保存真实输出 |
| 用量和请求标识 | 成本、失败恢复、对账 | 记录 usage 与 request_id；检查网关账单对齐方式 |

已通过的控制路径为 GPT Responses 和 Claude Chat Completions，当前不需要为此绕行其他协议。不能把自然语言里写一个工具名字冒充已验证的原生工具调用。

若 Images 编辑不通，优先补网关的图像编辑通道或直接接一个图像编辑服务；增加十个聊天模型不能解决此缺口。

## 缺口与需要补充的资源

1. 抠图与蒙版：目录未发现明确的专用模型或 API。优先评估本地分割/抠像方案，依据硬件、许可证和商品边缘效果选择；不急于购买额外通用模型。
2. 图像编辑通道：当前凭据分组 GT_INNER (distributor) 没有三个图像候选的可用通道，需修复分组、模型映射或上游通道；没有成功产物，不能评价编辑效果。
3. 实际计价与预算：已有六次成功推理的 usage，公开倍率仍不能直接换算当前 token 实际结算金额；Claude 兼容 usage 的字段口径存在差异，详见实测报告；model_price=0 不代表免费。
4. 模型上游区域与数据策略：网关在局域网不代表图片不会被转发到外部供应商；真实商品数据试点前明确上游与保留策略。

本轮是用户明确授权的有限接口测试，实际十一条请求、无自动重试，可能产生推理费用；真实金额未对账，不填为零。未修改网关分组或管理配置，也未上传真实商家素材。后续批量实验仍需确定总预算。

## 初始测试顺序

工具续接和双图理解已有通过路径；下一步修通图像通道，再测实际编辑效果、严格结构化输出及费用记录。相关功能冒烟通过后才进入十二 SKU 的 S0 效果评测。普通文本回复成功不能替代工具循环、图像输入或编辑测试。

若候选通过这些实测，即可用现有网关开展首版；若失败，再明确告知缺的是哪类接口或模型能力，避免无方向采购。
