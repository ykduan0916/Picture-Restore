# 迭代路线与优先级

按风险与依赖安排工作：先验证保真和协议，再完成单 SKU，再扩展批量，最后做真实商家试点。阶段以退出条件推进，不把日历到期当成完成。

人员、投入时间、预算尚未确定，因此不承诺具体上线日期。S0 完成后依据实际工作量与团队容量再制定排期。

## 优先级原则

| 级别 | 判断原则 | 例子 |
| --- | --- | --- |
| P0 | 缺失会导致商品失真、数据丢失、无法交付或不可控支出 | 主体保护、文档版本、费用上限、单 SKU 闭环 |
| P1 | 明确减少重复劳动、支持已验证的工作流规模化 | 品牌模板、批量任务、异常审核 |
| P2 | 有价值但需额外场景与收益验证 | 更多品类、平台连接、进阶创意、其他导出格式 |

框架数量、Agent 数量和界面炫酷程度不能单独提高优先级。同级任务先处理影响关键路径和不可逆风险的部分。

## S0 验证与工程契约

目标：证明关键路径可行，暴露模型、画布和恢复机制的限制。详细执行项见 [首轮清单](07-first-iteration-backlog.md)。

先后顺序：样本与任务定义 → 严格契约与工具接口 → 假供应商四角色流程 → 主体保护与可编辑文字 → 渲染与导出 → 真实模型对比 → 恢复及费用实验。

允许并行：契约定义完成后，画布渲染验证与后台恢复验证可分别进行；真实模型评测需等待授权素材、提供商和预算准备好。

退出证据：

- 一份首发品类及排除素材清单；至少十二个授权 SKU 用于开发冒烟，不与锁定测试集重叠。
- 三类交付物的原型输出、可编辑文档和受保护区域检查结果。
- 四角色输入输出轨迹，包含一次设计与素材冲突和一次质检返工；可先用假供应商验证协议。
- 重复投递、Worker 中断、请求结果未知、旧版本晚到四类实验记录。
- 两个候选图像服务或“一个服务加保真合成基线”的同条件实测；预算不足则该项未完成，不宣称 S0 整体通过。
- 基础依赖锁文件和决策记录，明确模型版本、许可证、访问区域、费用与延迟。
- 至少一条控制模型路径通过工具调用续接与双图理解，一条图像路径完成原图与蒙版编辑；有图片用途和细节裁片协议。

失败处置：商品保真不可控则缩小品类或更换处理路径；不以增加 Agent 掩盖图像能力问题。渲染不一致先缩小图层操作集。通过条件为 G0，见验收文档。

## S1 单 SKU 完整闭环

目标：用户能在工作区完成一套可编辑、可恢复的商品素材。

建设顺序：

1. 项目、SKU、原图与事实来源，完成鉴权和存储隔离。
2. 文档、图层、蒙版、历史版本，统一手动与 Agent 工具入口。
3. 规划与设计输出，接入修图执行和质量验收。
4. 任务状态、SSE、费用、取消与恢复；不能留到上线前补。
5. 问题定位、局部返工、人工接手、导出清单。
6. 锁定版本，完成 P0 功能和盲评。

交付证据：一条真实非 mock 的端到端路径、P0 用例结果、视觉评测报告、费用与耗时报告。通过 G1 才进入批量扩展。

## S2 品牌复用与小批量

目标：把单张成功扩展到稳定的一批。

建设顺序：品牌规范与模板版本 → 样板确认 → SKU 子任务展开 → 限流及批次预算 → 失败隔离和部分导出 → 批次一致性审核。

第一批次上限二十个 SKU，先验证而非默认追求千图并发。复用设计配置，但不跨用户复用私有图片、价格或商品事实。

交付证据：同一批次二十个 SKU，含失败、取消、重启与中途改版场景；成功项可交付，异常项有原因，不会串 SKU 或跨版本。通过 G2。

## S3 小规模商家试点

目标：证明实际节省人工并获得持续使用信号。

暂定邀请三至五个商家，至少完成三十个真实 SKU 任务包。先记录原工作流，再用相同类型任务对照；原型阶段的自选漂亮样例不能替代商家任务。

建设重点：失败热点修复、删除与备份恢复、预算告警、版本回滚、支持流程、用户反馈标注。新增功能只处理真实阻塞交付的问题。

通过 G3 后再决定扩大投入。付费、转化率和商业盈利另行验证，不能从节省修图时间推出销售增长。

## S4 按证据扩展

候选优先级由试点数据决定：

| 候选方向 | 启动条件 | 主要风险 |
| --- | --- | --- |
| 更多品牌模板和平台尺寸 | 高频重复制作、模板能明显减少人工 | 模板膨胀与平台规则过期 |
| 新商品品类 | 有真实需求与独立测试集，保真门槛可达 | 材质和形状能力不足 |
| 更复杂的营销设计 | 基础交付稳定，设计返工为主要成本 | 审美评价不稳定 |
| 团队审核与权限 | 多人交接是已验证瓶颈 | 权限、版本冲突 |
| 平台或素材库连接 | 手工导入导出成为主要耗时 | 授权、平台 API、误发布 |
| 更强模型或独立 QA 模型 | 同条件评测产生可重复收益 | 费用、延迟、版本漂移 |

不默认承诺视频、虚拟试穿、训练专有大模型、开放 Agent 平台或通用 Photoshop 替代。

## 需求变更规则

新增需求记录用户问题、预期收益、依赖、验收方式和机会成本，再放入对应阶段。变更影响已有 TaskContract、Document 或评测规则时必须升版本并说明迁移方式。

发现阻断问题时暂停进入下一阶段；修复后重跑受影响用例和必要回归，不无条件重跑全部昂贵模型评测。模型、提示词、渲染器或保护策略变更必须重跑对应质量集。
