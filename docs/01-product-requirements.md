# 产品要求

本文件定义第一版的产品范围。所有技术选择都应能对应用户任务、质量要求或成本约束。产品暂名 Picture Renew，不代表已确定品牌名称。

## 用户与任务

首批目标用户暂定为中小电商团队的运营与设计人员，需要反复处理商品上新、活动改版和多尺寸输出。该定位是待访谈验证的假设，不把“愿意试用”等同于“愿意付费”。

第一条完整任务：上传一个 SKU 的真实商品图片和资料，得到白底图、场景图、促销图各一张；每张可审核，促销文字可单独修改，随后导出整套文件。

示例：耳机原图、商品名、人工填写的活动价格和品牌 Logo → 主体保留 → 夏日场景 → 品牌促销排版 → 质量检查 → 用户确认交付。

## 首版素材边界

暂定优先轮廓清晰、不透明、主体完整的刚性商品，例如非镜面数码配件。S0 用真实素材选定一个首发品类；不一次覆盖全部电商品类。

试验性输入约束：JPEG、PNG、WebP；单图不超过 20 MB 和 20 MP；最长边不超过 8192 px。检查实际解码格式、像素数和 EXIF 方向，不信任扩展名。低分辨率与被遮挡商品显示适用性提示，不承诺修复不可见细节。

首版排除透明玻璃、强镜面反射、复杂毛发、珠宝微小镶嵌、服装上身、虚拟试穿、改变商品视角及大幅重打光。遇到这些素材应说明限制或转人工，不能静默生成近似商品。

## 工作区与主要流程

工作区包含商品资料、素材与图层、画布预览、任务进度、质量问题和导出。进度显示可观察到的步骤状态，不伪造模型内部百分比。用户无需理解 Agent 角色才能使用产品。

1. 上传并完成输入检查，填写或确认商品事实。
2. 选择交付物与风格；涉及缺失价格等必要事实时补充信息。
3. 系统制定任务与设计方案，准备商品主体；已有模板可直接执行。
4. 展示低成本预览或候选；新品牌方向可先选样板。
5. 制作、检查、在额度内局部修复；不确定项显示待人工复核。
6. 用户修正蒙版、文字或布局；保存版本。
7. 用户确认后导出图片与清单，保留可编辑项目。

不默认让用户批准每一次工具调用。必须补充信息、改变受保护商品内容、超过现有额度时才打断流程。

## 商品保真规则

默认使用保真合成模式：商品内部像素来源于原图；允许记录在案的缩放、位移和必要的边缘蒙版处理。商品比例、零件、标签、Logo、纹理和颜色不得被生成模型重新解释。

保护区域与边缘过渡带必须分别保存。验证应在相同变换和色彩管线下对照受保护区域，不能拿不同尺寸的图直接算像素差。边缘处理仍需检查是否切掉接口或细节。

生成式改商品、改变角度和重建缺失细节不属于第一版。未来若加入，需独立模式、明确风险提示和专门评测，不能沿用保真模式的承诺。

场景图优先生成背景并合成原商品。接触阴影使用独立层。视觉不协调不能通过偷偷重绘商品来修复。

## 营销与品牌规则

文字、价格、单位与 Logo 使用独立图层；版式按字体、字重、行距、边距与占位区域描述。首次缺少品牌规范时使用明确标为默认的模板，不能伪称已理解品牌。

用户输入的价格与规格是事实字段；Agent 可以组织措辞，不能推导未提供的功效、销量、优惠幅度或认证。平台模板有来源与更新时间，不宣传“自动保证平台审核通过”。

首版仅交付静态图片和本应用可编辑文档，不承诺完整 PSD 往返、印刷色彩管理、实时多人协作、视频或自动发布到平台。

## 完成与失败的定义

单 SKU 只有在所有要求的交付物生成、检查完成、无未解决阻断问题且用户确认后，才是“已接受”。程序跑完只能称“处理完成”。

达到重试上限、素材不足、关键事实缺失、预算不足或供应商调用状态未知时，应进入明确的待处理状态。失败结果不能混入合格导出包；允许单独下载带明确标识的草稿。

自动检查合格不等于用户接受。两种状态分别记录，避免用模型评分替代实际可用率。
